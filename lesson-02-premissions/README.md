# Урок 02 — Права доступа: chmod, chown, umask

## 1. Модель прав в Linux

Каждый файл имеет три класса доступа:

| Класс | Буква | Кто это |
|---|---|---|
| **u**ser | `u` | Владелец файла |
| **g**roup | `g` | Группа файла |
| **o**thers | `o` | Все остальные пользователи |

И три действия:

| Право | Буква | Число | На файле | На директории |
|---|---|---|---|---|
| **r**ead | `r` | 4 | Читать содержимое | Видеть список (`ls`) |
| **w**rite | `w` | 2 | Изменять содержимое | Создавать/удалять файлы внутри |
| e**x**ecute | `x` | 1 | Запускать программу | Заходить внутрь (`cd`) |

## 2. Числовая нотация

| Число | Бинарно | Символы | Значение |
|---|---|---|---|
| 7 | 111 | `rwx` | полный доступ |
| 6 | 110 | `rw-` | чтение + запись |
| 5 | 101 | `r-x` | чтение + исполнение |
| 4 | 100 | `r--` | только чтение |
| 0 | 000 | `---` | нет доступа |

Примеры:
- `chmod 700 file` — только owner
- `chmod 755 script.sh` — стандарт для исполняемых скриптов
- `chmod 644 file` — стандарт для обычных файлов
- `chmod 600 secret.ini` — только owner (пароли, ключи)

## 3. Символьная нотация

- `chmod u+x file` — добавить owner исполнение
- `chmod g-w file` — убрать у group запись
- `chmod o=r file` — установить others только чтение
- `chmod a+x file` — добавить всем исполнение

## 4. chown — смена владельца

```bash
chown user:group file         # сменить owner и группу
chown -R user:group dir       # рекурсивно
sudo chown root:root file     # от имени root
```

## 5. Права на директории

| Право | Что даёт |
|---|---|
| `r` | Видеть список файлов (`ls`) |
| `w` | Создавать/удалять файлы внутри |
| `x` | Заходить внутрь (`cd`) |

> Важно: право на удаление файла определяется правами **родительской директории**, а не самого файла.

## 6. umask

Определяет, какие права **убираются** при создании файла.

- `umask 022` (дефолт): файлы `644`, директории `755`
- `umask 077` (paranoid): файлы `600`, директории `700`

## 7. Почему `777` — антипаттерн

`chmod 777` даёт любому пользователю полный контроль. В продакшене это:
- Возможность перезаписи бинарников скомпрометированным сервисом
- Privilege escalation
- Нарушение принципа least privilege

**Правильные права по умолчанию:**

| Объект | Права | Почему |
|---|---|---|
| Обычный файл | `644` | Владелец редактирует, остальные читают |
| Исполняемый скрипт | `755` | Владелец запускает, остальные тоже |
| Конфиг с паролями | `600` | Только владелец |
| Лог-директория | `755` или `775` | Сервис пишет, структура не меняется |
| SSH-ключи | `600` | OpenSSH требует строгих прав |

## 8. Pet Project: setup_env.sh

Скрипт создаёт структуру `~/myapp/` с правильными правами:

| Объект | Права | Назначение |
|---|---|---|
| `bin/` | `750` | Только owner и group |
| `bin/run.sh` | `750` | Исполняемый скрипт |
| `etc/config.ini` | `600` | Конфиг с production |
| `var/log/` | `755` | Все заходят, пишет owner |
| `var/log/app.log` | `644` | Лог читаем всем |

Запуск:
```bash
chmod +x setup_env.sh
./setup_env.sh
```
